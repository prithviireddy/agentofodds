## SEC access proof

Set `SEC_USER_AGENT` locally to the application name plus a real contact email (a declared identity for SEC requests, not an API key). Keep this value in your shell environment or ignored `.env`, never in tracked files.

```powershell
uv run --locked python -m backend.app.sec_probe
# If using a local .env file instead of a shell environment variable:
uv run --locked --env-file .env python -m backend.app.sec_probe
```

Verified so far: without the setting, the first command exits 1 with `missing_configuration` before any network call. The configured live path and `.env` invocation are pending verification. The probe resolves current ticker/CIK mappings, requests CompanyFacts and recent submission metadata, and selects an eligible USD Assets sample and filing reference per company. It prints JSON; it does not download filing bodies or cache raw responses. Output records source URLs, retrieval times and response hashes, but does not contain the contact header.

Limits: one sequential request per second, 12 requests per run, 20-second timeout per request, 25 MB per response, no automatic retries or redirects. A five-company run needs 11 requests. Larger universes require deliberate batching in later work. Reported success covers only this narrow SEC probe; it does not establish live prices, news, model access or historical-dataset completeness.

## M1.1 policy and numerical contracts — 2026-09-21

M1.1 is complete. `InvestmentPolicy` requires an explicit cutoff, universe, capital, USD currency, supported objective, asset/cash bounds and review frequency. It rejects infeasible constraints before optimisation. `PriceInput` requires provider/feed/adjustment/currency/hash/retrieval provenance and derives missing-symbol status from its bars. An input is marked point-in-time eligible only when its availability status is explicitly verified.

No user investment policy is configured yet. The test policy uses minimum variance and sample bounds only to validate the contract; it is not a recommendation or application default.
## M1.2 numerical baseline — 2026-09-21

M1.2 is complete. The numerical core uses aligned simple close-to-close returns and sample covariance with Bessel’s correction (`ddof=1`). It requires three aligned sessions to form two returns and refuses unverified point-in-time price inputs. The long-only projected-gradient optimiser minimises `w'Σw` under explicit per-asset bounds and cash bounds, validates symmetric positive-semidefinite covariance, and returns `success`, `infeasible`, or `failed_validation` with diagnostics.

For this minimum-variance baseline, cash is modelled as zero variance and set to the maximum permitted cash level; this convention is visible in output diagnostics. It is an initial mathematical convention, not a user policy default or forecast.
