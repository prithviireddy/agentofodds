# Delivery specifications

A FEAT defines a bounded increment before implementation: the problem, contracts, exclusions, acceptance criteria and verification route. It is not a second architecture reference. Completed behavior is folded into platform chapters.

Use [TEMPLATE.md](TEMPLATE.md) and the next unused `FEAT-NNNN-short-title.md`. Status is proposed, ready, in progress, blocked, done or deferred. The user's request can supply authorization for its actual scope; do not add an approval ceremony to routine reversible work. Record missing decisions if they materially block delivery.

| ID | Scope | Status |
| --- | --- | --- |
| [FEAT-0001](FEAT-0001-documentation-foundation.md) | Consolidate repository documentation and preserve demo-package portability | Done; scoped closeout evidence recorded |

Earlier M0–M5.3 and UI.1 remain historical milestone IDs in [docs/tasks.md](../tasks.md). Their enduring behavior is already in platform chapters; no retrospective FEATs are created. Unselected future work belongs in [deferred](../deferred/README.md).
