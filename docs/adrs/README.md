# Architectural decisions

An ADR records a consequential new architectural decision and its rationale. Use the triggers in the [platform change process](../platform/README.md#change-process), rather than creating one for every edit.

No ADRs are backfilled for the existing foundation. The current baseline is documented in platform chapters. No new runtime architecture decision is made by the documentation consolidation.

For a new decision, copy [TEMPLATE.md](TEMPLATE.md) to `ADR-NNNN-short-title.md` using the next unused number. Status is proposed, accepted, rejected or superseded. Record the actual acceptance basis and affected chapters; do not invent an owner review. Accepted changes update the platform and link the implementing FEAT. If an accepted requirement is not implemented yet, label it Target there.
